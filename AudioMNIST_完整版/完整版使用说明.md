## 环境与使用

解压到普通本地目录，进入本文件所在文件夹。推荐 Python 3.12，依赖需要安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python run_pipeline.py compare
.\.venv\Scripts\python run_pipeline.py ensemble
```

以上两条分析命令直接读取已有逐折结果，不需要重新训练。分析输出分别进入 results/comparison/ 和 results/ensemble_equal_weight.json。analysis/ 保存本次人工解读与已计算的比较文件。

单条不超过 1 秒的单声道 WAV 预测：

```powershell
.\.venv\Scripts\python predict_ensemble.py --wav YOUR_RECORDING.wav
```

该命令使用包内三个 MFCC 增强全量模型等权平均概率。单条预测不是独立测试成绩。

核验某个已有完整实验：

```powershell
.\.venv\Scripts\python verify_saved_run.py runs/main/mfcc_delta__logistic__augmented/result.json --out results/check_logistic.json
```

## 重新训练与旧记录

原主批次保存的是当时源码指纹；最新版增加了功能，evaluation.py 指纹已变化。直接恢复旧 main 批次会触发配置一致性检查。需要重新训练时，使用一个新的 run-id，例如：

```powershell
.\.venv\Scripts\python run_pipeline.py train --run-id rerun_latest --jobs 3
```

原 run_pipeline.py verify/verify.py 的全目录核验要求历史源码与当前源码完全相同，不能在混有多版源码产物的这个归档中直接使用。请用 verify_saved_run.py 分别核验逐折人员隔离、内层选参及已保存概率的指标复算；它不会冒充原始音频到模型的全流程重跑。完整原始源码和原有核验记录保存在 provenance/baseline_snapshot/。默认 compare 和 ensemble 分析的是 runs/main；新 run-id 可通过独立脚本的路径参数分析。

## 目录与实验状态

- runs/main：原 12 组主实验，共 120 个外折模型及 12 个全量模型。
- runs/alt_min_child：MFCC LightGBM 改调最小叶样本数，两种训练方式各完整 10×3。干净训练通过中间值检查，增强训练未通过。
- runs/multi_snr_20261010：Log-Mel、MFCC 两组逻辑回归的双强度白噪声实验，各完整 10×3，均通过中间值检查。
- data_raw：原始音频归档及许可；data：两种特征缓存及样本清单。
- analysis：结果比较、参数审查和本轮模型精进说明。
- provenance：历史源码、环境版本、参数诊断与原核验记录。

未完成的双强度 LightGBM 批次没有纳入完整模型目录，其未完成状态记录在 PACKAGE_MANIFEST.json。新等权集成的粉红噪声 macro-F1 为 0.9414，是看过原结果后补做的探索性分析，不是独立确认实验。原 MFCC 干净训练的两组调参失败仍保留，不应把所有配置声称为作业全面合规。
